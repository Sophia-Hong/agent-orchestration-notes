코딩을 시작하기 전에 구현 스펙을 먼저 작성한다.

## 현재 이해 확인

코드베이스를 충분히 파악하고 있는가?
- 파악하고 있으면 → 직접 스펙 작성
- 더 조사가 필요하면 → `/research` 먼저, 결과 도착 후 스펙 작성

## 스펙 구조

### 문제 / 목표
한 문장으로: 무엇을 왜 바꾸는가.

### 변경 범위
```
수정할 파일:
  - [파일 경로]: [어떤 부분을, 왜]
  - [파일 경로]: [어떤 부분을, 왜]

건드리지 않을 파일:
  - [파일 경로]: [이유]
```

### 구현 접근 방식
단계별로: 무엇을 먼저 하고, 무엇을 나중에 하는지.
의존성이 있는 순서라면 그 이유도 포함.

### 완료 기준
- [ ] 통과해야 할 테스트 명령
- [ ] 타입체크 / 린트 통과
- [ ] 검증할 동작 (curl 예시, 실행 예시 등)

### 리스크 / 주의사항
- 예상되는 side effect
- 기존 동작이 바뀌는 부분
- 되돌리기 어려운 변경

---

스펙 작성 후 확인을 구하거나, 바로 구현을 시작할지 물어본다.
